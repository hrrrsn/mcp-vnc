# Code Review — 2026-07-20

**Scope**: Full codebase review of `hrrrsn/mcp-vnc` (v1.0.2) — 9 TypeScript files, ~1300 LOC
**Reviewer**: opencode (code-reviewer skill)
**Axes checked**: correctness, security, performance, maintainability

---

## Findings

### File: src/vnc/client.ts

- **Critical Fix** (L77-79): Connection timeout (`setTimeout`) is set unconditionally but never cleared on success. The timer leaks memory and could fire after `resolve()` causing unexpected errors. Store the timer ID and call `clearTimeout` in the `frameUpdated` and `error` handlers.

- **Critical Fix** (L35-56): Race condition between `authenticated` and `frameUpdated`. If `frameUpdated` fires before `authenticated` completes, `hasReceivedInitialFramebuffer` may already be `true` when the second event fires, but the connection promise only resolves from within `frameUpdated` — which may have already happened. The `resolve(vncClient)` call should be moved to `authenticated` handler, or a separate state variable should track "ready" status.

- **Important** (L13-21): `executeWithConnection` creates a NEW VNC connection for every single tool call. Each click, keypress, or screenshot opens a fresh TCP connection, handshakes, authenticates, requests a framebuffer update, then disconnects. This adds seconds of latency per operation and is architecturally wrong. Should maintain a persistent connection that is lazily initialized and shared across tool calls.

- **Important** (L96): `validateCoordinates` returns `{ valid: true }` when `screenWidth === 0 || screenHeight === 0`. This allows coordinates to pass validation silently when dimensions aren't yet known, potentially sending out-of-bounds clicks. Should return `{ valid: false }` with an appropriate error.

### File: src/tools/screenshot.ts

- **Important** (L140-168): Dead code — `convertBGRXToRGBA` is defined but never called anywhere in the codebase. Remove or integrate (it's good code, but unused = untestable = tech debt).

- **Important** (L118-131): `needsPixelFormatConversion` is also dead code — never called. The screenshot handler goes straight to `convertToRGBA` based on `actualBytesPerPixel !== 4`, never checking the pixel format flag first.

- **Minor** (L11-12): Corruption detection samples only the first 1000 pixels (`Math.min(1000, width * height)`). For a 1920×1080 screen (2M pixels), sampling ~0.05% of pixels may miss corruption entirely. Consider stratified sampling across the entire framebuffer.

- **Minor** (L295-313): The auto-resize threshold (800KB) and JPEG quality levels (80/75) are hardcoded magic numbers. High-resolution displays may constantly hit resize, losing detail. Consider making these configurable or scaling proportionally.

- **Suggestion** (L1-335): This file is 335 lines and mixes 3 concerns: corruption detection (L5-50), pixel format conversion (L52-169), and screenshot capture + encoding (L171-335). Should be split into `pixel-format.ts`, `screenshot.ts`.

### File: src/tools/input.ts

- **Important** (L170-173): `typeString` sends characters one-by-one via VNC with 100ms delay between characters for long/special-char text. For a 100-character string, that's 10 seconds. VNC supports sending multiple key events in a single frame update. Consider batching or using clipboard paste where possible.

- **Minor** (L23-L26): Redundant `||` fallback — `args.button` already defaults to `'left'` via MCP tool schema, and `buttonMap[button]` falls back to `buttonMap.left`. The double-fallback is harmless but unnecessary.

- **Minor** (L209-L211): The `catch` wraps the error in a new message but loses the original stack trace. Use `error instanceof Error ? error : new Error(String(error))` to preserve the cause chain.

### File: src/index.ts

- **Important** (L6-14): The `uncaughtException` handler silently swallows ALL VNC compression errors (`Z_DATA_ERROR`, `invalid distance too far back`). While this prevents crashes from a known library quirk, it also masks:
  - Real data corruption
  - Different errors with similar messages
  - The frequency of these errors (no metrics/logging beyond `console.error`)
  
  Consider: logging to a metric, limiting suppression count, or fixing the root cause in the VNC library.

- **Minor** (L24): `VNC_PASSWORD` is read from environment variable (good — not hardcoded). However, environment variables are visible in process listings (`ps`, `/proc`, Task Manager) and could be logged by monitoring tools. Consider supporting a password file option.

### File: src/server.ts

- **Minor** (L13): `readFileSync(join(__dirname, '../package.json'), 'utf-8')` executes synchronously at module import time, blocking the event loop. For a CLI tool this is negligible (<1ms), but noted for correctness.

- **Suggestion** (L153-160): The `catch` block wraps all tool errors into a uniform text response. While this follows MCP conventions, it loses error types — the AI agent can't distinguish "VNC connection down" from "invalid coordinates". Consider adding error codes or categories in the response.

### File: src/vnc/keyboard.ts

- **Minor** (L79-83): `getKeysym` maps shifted symbols (`!@#$%^&*()_+...`) to direct keysym codes. However, `typeCharacter()` in `input.ts` sends the *unshifted* key + Shift modifier for these characters. The direct keysym entries may never be reached through the normal typing path, making them dead entries. Verify the intended usage or remove them.

### File: src/test.ts

- **Minor** (L91): `(initTimeout as any)._destroyed` — accesses an internal, undocumented Node.js property. This is fragile and will break across Node.js versions. Track state explicitly with a boolean flag.

- **Minor** (L456): `if (!process.env.VNC_HOST && process.env.VNC_HOST !== 'localhost')` — this condition is always `true` when `VNC_HOST` is unset (since `undefined !== 'localhost'`). The `!== 'localhost'` check is dead logic. Simplify to `if (!process.env.VNC_HOST)`.

- **Suggestion** (L107-153): Test methods hardcode the `test-output` directory. If the server runs in a different cwd, screenshots land in unexpected places. Use an absolute path or configurable output directory.

### Verdict: **Needs fixes**

The two Critical issues (race condition + timer leak) must be resolved before relying on this in production. The architectural decision to open a new VNC connection per tool call (Important) will cause unacceptable latency — a persistent connection model is strongly recommended.

### Key Strengths
- Well-structured MCP integration with clean tool definitions
- Good pixel format conversion coverage (RGB24, RGB565, palette)
- Thoughtful corruption detection heuristics (even if sampling-limited)
- Comprehensive test suite covering all tools + edge cases (delay, double-click, combinations)
- Proper use of `finally` for cleanup in `executeWithConnection`
- Environment-variable-based configuration (no hardcoded credentials)
